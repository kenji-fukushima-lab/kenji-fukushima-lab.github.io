# Website audit — 2026-09-08

Four defects were reproduced and fixed:

- Resources cards overflowed narrow screens and obscured repository names and
  statistics. The cards now stack and wrap at narrow widths. Regression tests
  cover English/Japanese pages at 320, 390, and 768 pixels.
- A failed Pagefind script download left a permanently rejected promise, so
  reopening search never retried. Failed downloads now reset the loader, and
  successful retries clear the error message. The recovery instruction is
  localized for Japanese pages.
- Denied browser storage reads or writes interrupted theme initialization and
  search. The active theme now works in memory when persistence is unavailable;
  saved preferences are still read and written when permitted.
- A missing YAML comma combined the BibTeX `website` and `url` exclusion entries.
  The two fields are now filtered separately, with DOI and title retention tested.

Each regression test failed before its corresponding fix and passed afterward.

## Validation

- Production Jekyll build, Pagefind indexing, and CSS optimization passed.
- `npm run checks:push` passed: 64 Python tests, 14 JavaScript tests, 17 Ruby tests
  (105 assertions), bibliography validation, image budget, and formatting.
- All 80 Playwright tests passed, including the existing axe accessibility sweep,
  desktop/mobile and light/dark modes, search, publication filters and access
  dialogs, blog pagination, repository statistics, maps, and responsive images.
- All 155 generated HTML pages were scanned for local `href`, `src`, and `poster`
  targets, fragment anchors, and duplicate IDs; no defects remained.
- Both Atom feeds and sitemap destinations passed their validators. All 1,871
  local responsive-image width descriptors matched their actual image files.
- Additional browser inspection covered ten representative routes at 390 and
  1,440 pixels. No uncaught page errors or broken loaded images were observed.
  The Resources overflow found in this sweep was fixed and visually rechecked.
- Lighthouse passed three samples each for `/`, `/ja/`, `/publications/`, and
  `/ja/publications/`. Accessibility, best practices, and SEO scored 100 in all
  twelve reports. These measurements are validation, not a speedup comparison.
- Lighthouse also passed three samples each for `/resources/` and
  `/ja/resources/` after the layout fix. Accessibility and SEO scored 100;
  best practices scored 96. GitHub API requests returned 403 during this run,
  producing console warnings while the build-time statistics remained visible.

## External links and limits

An unauthenticated GET scan checked 498 distinct external links in generated
HTML: 427 returned 2xx, 69 returned 403, one returned 999, and one returned 404.
The 404 target, `kfuku52/kflab`, is explicitly documented as an invitation-only
private repository. It was retained. The access-denied responses do not establish
whether the destinations work for a signed-in human visitor; none were removed
or silently excluded.

Validation used local Chrome with Ruby 3.4.8, Node 26.3.0, and Python 3.14.5.
The pinned CI runtime combination, Safari/Firefox, live form delivery, and every
state of external services were not exercised. The production publication
workflow was not run as part of this local commit.
